# Исправление: Только API СДЭК (без fallback)

## Проблема
Система использовала fallback расчет с фиксированной ценой 350 рублей вместо реального API СДЭК, что приводило к неточным расчетам стоимости доставки.

## Причина
- В PHP коде был fallback метод с базовой ценой 300 руб
- В JavaScript был fallback метод с базовой ценой 350 руб  
- При ошибках API использовался fallback вместо настоящего расчета

## Исправления

### ✅ 1. Удален PHP fallback
**Было:**
```php
private function calculate_fallback_cost($weight, $value, $dimensions, $has_real_dimensions) {
    $base_cost = 300; // Базовая стоимость
    // ... дополнительные расчеты
    return $base_cost;
}
```

**Стало:**
- Метод полностью удален
- При ошибке API возвращается реальная ошибка

### ✅ 2. Удален JavaScript fallback
**Было:**
```javascript
function calculateFallbackCost(point, cartData) {
    var baseCost = 350; // Базовая стоимость
    // ... дополнительные расчеты  
    return baseCost;
}
```

**Стало:**
- Функция полностью удалена
- При ошибке API показывается сообщение об ошибке

### ✅ 3. Изменен AJAX обработчик
**Было:**
```php
// ИСПОЛЬЗУЕМ РЕЗЕРВНЫЙ РАСЧЕТ
$fallback_cost = $this->calculate_fallback_cost(...);
wp_send_json_success(array('delivery_sum' => $fallback_cost));
```

**Стало:**
```php
// Возвращаем ошибку - только API расчет
wp_send_json_error(array(
    'message' => 'Не удалось рассчитать стоимость доставки СДЭК. Попробуйте выбрать другой пункт выдачи.'
));
```

### ✅ 4. Улучшена обработка ошибок в JavaScript
**Было:**
```javascript
// Используем fallback вместо показа ошибки
var fallbackCost = calculateFallbackCost(point, cartData);
if (callback) callback(fallbackCost);
```

**Стало:**
```javascript
// Показываем ошибку пользователю вместо fallback
console.error('❌ API СДЭК вернул ошибку:', response.data.message);
if (callback) callback(null);
```

### ✅ 5. Добавлена проверка результата
```javascript
if (deliveryCost === null || deliveryCost === undefined) {
    console.error('❌ Не удалось рассчитать стоимость доставки');
    
    // Показываем ошибку пользователю
    labelElement.text('Ошибка расчета доставки СДЭК');
    valueElement.text('Попробуйте другой ПВЗ');
    return;
}
```

## Результат

### 🎯 Теперь система работает так:
1. **API СДЭК работает** → Показывается точная стоимость от СДЭК
2. **API СДЭК не работает** → Показывается понятная ошибка пользователю
3. **Никаких фиксированных цен** → Только реальные расчеты

### 📊 Преимущества:
- ✅ **Точные цены** - только от API СДЭК
- ✅ **Прозрачность** - пользователь знает, если есть проблемы
- ✅ **Надежность** - API СДЭК работает стабильно
- ✅ **Отсутствие путаницы** - нет разных цен от разных источников

## Диагностика API СДЭК

### Проверьте логи для диагностики:
```
СДЭК расчет: ✅ Успешно рассчитана стоимость через НАСТОЯЩИЙ API: XXX
```

### Если API не работает, в логах будет:
```
❌ СДЭК API: Некорректный HTTP код
❌ СДЭК API: API вернул ошибки
❌ СДЭК расчет: Альтернативные методы не сработали
```

### Возможные проблемы и решения:

#### 1. Ошибка авторизации (HTTP 401)
**Причина:** Неверные учетные данные СДЭК
**Решение:** Проверить настройки плагина:
- `cdek_account` - ID клиента
- `cdek_password` - Секретный ключ

#### 2. Ошибка параметров (HTTP 400)  
**Причина:** Неверные данные запроса
**Решение:** Проверить:
- Корректность кода города отправления (Саратов = 354)
- Правильность габаритов и веса товаров
- Корректность кода пункта выдачи

#### 3. Город/ПВЗ не найден
**Причина:** Неверный город назначения или код ПВЗ
**Решение:** 
- Выбрать другой пункт выдачи
- Проверить правильность определения города из адреса

#### 4. Ошибка сервера СДЭК (HTTP 500)
**Причина:** Временные проблемы на стороне СДЭК
**Решение:** Подождать и попробовать позже
